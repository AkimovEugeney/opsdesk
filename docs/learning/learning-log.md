## System Health Review — 2026-09-23

Requested by the learner after the OPS-006 scaffolding session, in which about an hour of session time produced a NestJS module skeleton, a two-field DTO and one service method. Findings, from the session dialogue:

- **Unprobed commands.** The `nest` binary was assumed to exist (twice), one command was handed over as unexecutable markup, the working directory was never stated (a package-manager run in the repository root left `node_modules/`, `package.json` and `package-lock.json` there), and a missing `--flat` put the DTO in a nested folder. Four round trips were spent on mentor tooling rather than on the learner's work.
- **Serialised micro-steps.** Constructor field casing, the `!` marker and the DTO definition each cost two turns, and one style note was reversed a turn later. The learner's recorded preference for connected 2–4 action blocks, and the existing rule to answer an evident local question directly, were not applied.
- **Misdirected scrutiny.** Prisma's `where`/`select` spelling was treated as material for the learner to derive, although `prisma-reference` is LOOKUP in learning-state.json, and no worked example had been given for a construct the learner had never written; three turns went into `true` flags. A missing `npx prisma generate` after the schema change was fixed silently and first surfaced to the learner as "we forgot something".
- **Contradiction.** "The CLI is not needed for this ticket, create the files by hand" was followed two turns later by CLI generator commands.
- **Waiting between edits.** Handoffs asked for one field ("add `passwordHash`, then build") and then waited for a report before naming the next edit, so every one-line change cost a full round trip of learner waiting. The learner identified the waiting, not the code, as what consumed the session.

Accepted changes (three, applied in this file, `hint-policy.md` and `learning-contract.md`):

1. Commands are probed in this environment before handover and delivered as copy-pasteable text with the working directory, the files they touch and one expected observation; a command that fails on the learner's machine is a mentor process error, recorded in the ticket log.
2. A step is an observable artifact, delivered as connected 2–4 actions with exact strings, and a handoff never ends on a single field or line edit: it states the full set of edits for that artifact and names what comes after it. The learner reports back when a command fails, when a decision is needed, or when the artifact is complete. Style and API-shape notes are given once with their basis and are not reversed.
3. The first use of a library API surface is taught with a small worked example on different data plus the exact shape for the task; environment prerequisites after schema, migration or dependency changes are mentor-owned and run before dependent code is requested.

Not changed: ticket scope, the login contract, the order of OPS-006 work, and the learner's ownership of the implementation. No product scope or sprint commitment is created by this review.
