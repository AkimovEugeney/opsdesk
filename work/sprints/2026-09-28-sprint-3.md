## Known risks / unknowns

- The definition of “senior operator”, self-assignment and error behavior are agreed in [the OPS-003 requirements log](../tickets/OPS-003-requirements-log.md): an operator with `canManageAppeals` in an otherwise possibly empty per-user permissions list may assign themselves or another operator. The bounded list contains only this permission in OPS-003.
- `Permissions`, `User.permissions`, the migration, AuthModule wiring and protected-route endpoint are present in committed source. Do not plan them again.
- `AuthService.getCurrentUser` supplies trusted identity and permissions. Authorization is still the active learning mechanism because the learner's protected-write rationale and current behavior have not been verified.
- A read-before-write alone can race with a concurrent close. The design must preserve the closed-state invariant at write time without exposing a client-supplied actor identity.
- Runtime readiness was checked 2026-09-26: the PostgreSQL container is up on port 5433, ignored local environment files exist, dependencies are installed, and `npm run build` passes. No secrets were inspected.
- The API has no automated test suite. Manual verification must cover allowed assignment, denied actor, invalid/unsuitable assignee, missing appeal, closed appeal and a concurrent-state control; independent review remains required.
