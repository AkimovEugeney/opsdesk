## Visible requirements

- `GET /appeals` returns the active customer requests list.
- The list includes requests with `NEW` and `IN_PROGRESS` statuses only. It returns `NEW` first, then `IN_PROGRESS`; within each status requests are ordered from newest to oldest by creation date.
- Each list item includes `id`, `status`, `title`, `description`, `clientName`, `ownerName`, and `createdAt`. `ownerName` is `null` for a `NEW` request.
- When no active requests exist, the endpoint returns `200 OK` with `[]`.

## Acceptance criteria

- When no active customer requests exist, `GET /appeals` returns `200 OK` with `[]`.
- When `NEW`, `IN_PROGRESS`, and `CLOSED` requests exist, `GET /appeals` returns only `NEW` and `IN_PROGRESS` requests. `NEW` requests are listed before `IN_PROGRESS`, and each status group is ordered by creation date from newest to oldest.
- Every returned item includes `id`, `status`, `title`, `description`, `clientName`, `ownerName`, and `createdAt`. `ownerName` is `null` for a `NEW` request.
