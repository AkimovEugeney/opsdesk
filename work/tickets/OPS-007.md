Повторяемые проверки защищают назначение ответственного от регрессий: разрешённое изменение должно работать, запрещённое — не менять данные, а сбой базы не должен ошибочно выглядеть как штатный конфликт.

## Context

OPS-003 is Done: its HTTP behavior matrix, independent review and understanding check are complete. `AppealsService.approveOwner` contains an early authorization check and maps only a conditional-update Prisma `P2025` to `ConflictException`; other errors are rethrown. The repository has no test runner or `*.spec.ts` files. The exact concurrent-close branch cannot be made deterministic through the existing HTTP route because a closed appeal is rejected before its conditional update.

## Visible requirements

- One command runs the new API behavior tests locally and exits non-zero when an assertion fails.
- The tests cover an allowed protected assignment and a forbidden actor.
- A deterministic repository stub simulates Prisma `P2025` after the allowed preconditions and verifies the service conflict behavior.
- A different database/infrastructure error remains distinguishable from `P2025` and is not relabelled as a business conflict.

## Acceptance criteria

- The selected minimal runner executes TypeScript service tests without adding an external test framework.
- An allowed actor receives the selected assignment result from `AppealsService.approveOwner`.
- An actor without `canManageAppeals` receives `ForbiddenException`; the test proves no repository call is needed after the authorization decision.
- When `updateAppealOwner` rejects with Prisma `P2025`, the service rejects with `ConflictException` whose HTTP status is `409`.
- When `updateAppealOwner` rejects with an unrelated error, the test observes that same error object rethrown by the service, not a `ConflictException`.
- Existing API build remains green.

## Risks

- A test that simulates a closed appeal through the early read does not exercise the conditional-write race branch; only a stubbed `updateAppealOwner` rejection establishes this contract.
- Mapping every repository failure to `409` could hide an outage as a client conflict. The invariant is that only known `P2025` maps to `409`; the regression evidence is a test observing a different error unchanged.
