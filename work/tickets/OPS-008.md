## Context

The repository has an API but no frontend application. `GET /appeals` exists, but this ticket intentionally makes no network request: Nest has no CORS configuration and login/session integration remains outside scope. The user selected Next.js as the frontend foundation.

## Visible requirements

- A separate Next.js TypeScript application exists at `apps/web`.
- It starts locally with its documented npm command and renders a static Russian-language screen titled “Активные обращения”.
- The screen shows a product-appropriate empty state; it does not call the API, simulate authenticated data or require styling in this slice.

## Acceptance criteria

- `apps/web` installs and builds successfully.
- A local dev server renders the static active-appeals page.
- No API endpoint, CORS setting, cookie/session behavior, Prisma schema or migration changes.
- The page contains no hard-coded credentials, tokens or fake user identity.

## Intentionally excluded

- Fetching `GET /appeals`, CORS, login/logout, cookies, client-side session state, protected routes, appeal details, assignment and styling-system expansion.

## Risks

- Calling the API from the new browser app would cross an unconfigured origin boundary and could lead to a misleading workaround such as client-supplied identity. The invariant is that this static slice does not make a request or represent authentication; the rendered page and unchanged API are the evidence.
