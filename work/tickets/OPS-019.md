## Business value

Operators work from the active queue and customers from their own appeal list. Both return every matching appeal in one response. As the volume grows, the list becomes slow to load and heavy for clients to process, and a single request can pull the whole table.

## Context

- Both lists exist, are caller-scoped (OPS-015) and sorted newest first (the operator queue also by status). No page size or limit exists today. Optional title search exists on the same list.
- Backend API only. Web client OPS-016/011 stays deferred. No schema change is required by the business scope.

## Visible requirements

- A caller receives a bounded part of the list per request and can continue to get the rest, until the list ends. Sorting order and the caller-specific visibility rules stay as they are.
- The page size has a sensible default and a maximum; an invalid or oversize request is rejected with a clear 400 rather than silently changed.
- A client can tell whether more appeals exist.
- Walking all pages returns each matching appeal exactly once, with no repeats or gaps, in the existing order. Appeals created while a caller is paging must not make the caller see the same appeal twice.
- Search keeps working together with paging. Empty list or last page is a normal success.
- Existing detail, write and workload routes and their access rules are unchanged. Existing client behavior without paging parameters stays valid with the default page size.

## Acceptance criteria

- With more appeals than one page, the first request returns exactly the default number, in the existing order, and shows that more exist.
- Following the continuation to the end returns every visible appeal exactly once; a customer never receives another customer's appeals on any page.
- A new appeal inserted between two page requests does not cause a repeat or a skipped appeal for items already past.
- Invalid and oversize page size, and a malformed continuation, return 400; 401/403 behavior is unchanged.
- Search plus paging return only matching appeals, each once.
- Build, existing service tests and real HTTP observations pass; required review done.
